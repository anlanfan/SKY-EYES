## 1. 文件

| 文件 | 对应的原始文件 | 作用 |
|---|---|---|
| [`head_unit_optimized/head_unit_optimized.ino`](head_unit_optimized/head_unit_optimized.ino) | `../head_unit/head_unit.ino`（原名 `sketch_jan09a.ino`） | 头戴端：读取 MPU6050，通过 HC-05 发送 |
| [`receiver_optimized/receiver_optimized.ino`](receiver_optimized/receiver_optimized.ino) | `../receiver/receiver.ino`（原名 `sky_eyes_slave.ino`） | 接收端：接收角度，在 D2 输出 PPM |

Arduino IDE 要求 `.ino` 文件放在同名文件夹里，所以每个程序单独一个文件夹。

## 2. 没有改变的部分

- **硬件**：同样的开发板、MPU6050、HC-05，接线不变。
- **头戴端 → 接收端的数据格式**：9600 波特率；每个轴 1 字节，值为「角度 + 90」；俯仰发偶数、偏航发奇数；每 8 ms 发一个字节，两个轴交替发送；接收端忽略大于等于 200 的字节。
- **PPM 输出**：D2 引脚，8 通道，20 ms 一帧；每个通道是 500 µs 低电平加 N µs 高电平；第 1–6 通道固定 1500 µs，第 7 通道是俯仰，第 8 通道是偏航。
- **依赖库**：头戴端仍然只用 `MPU6050_light`，接收端不需要任何库。

## 3. 修改内容

### 头戴端 `head_unit_optimized.ino`

| # | 修改 | 原因 |
|---|---|---|
| H1 | 角度加 90 之后**限制在 0–180** | 原代码不限范围，超出 0–255 时 `Serial.write()` 会把数值截断，奇偶性也可能出错 |
| H2 | 去掉两个 `delay(8)`，改用 `millis()` 定时发送，仍然是每 8 ms 一个字节 | 原代码每 16 ms 才调用一次 `mpu.update()`。现在每次循环都调用，传感器融合计算更频繁 |
| H3 | 删除没有用到的代码：发送之后才执行的两行 `map()`，以及被注释掉的 `ppmsig_post()`、`chnum[]` | 这些代码不影响输出，删掉后程序更清楚 |
| H4 | 修正注释（原注释的奇偶写反了），把重复逻辑整理成 `encodePitch()` / `encodeYaw()`，数值改成命名常量 | 方便阅读 |

### 接收端 `receiver_optimized.ino`

| # | 修改 | 原因 |
|---|---|---|
| R1 | **修复数组越界**：原来 `chnum[8]` 却访问了下标 8，现在改成 0 起始的数组 | 原代码写到了数组外面，可能覆盖相邻变量 |
| R2 | **去掉每次循环的 `Serial.println()`**，改成 `DEBUG_PRINT` 开关，默认关闭 | 这个串口就是连 HC-05 的那个，打印的内容会通过蓝牙发回头戴端。发送缓冲区满了之后会阻塞，拖慢 PPM 输出 |
| R3 | **PPM 改用 Timer1 中断生成**（ATmega328P / 168，16 MHz） | 原来用 `delayMicroseconds()` 硬延时，会被其他中断拉长，造成脉宽抖动。改用硬件定时器后帧周期更准，主循环也不再被占满。其他开发板会自动退回原来的写法 |
| R4 | 每帧开始时一次性读取所有通道的值 | 避免一帧里新旧数值混在一起 |
| R5 | 同步间隔按实际通道值计算 | 原代码假设第 1–6 通道一定是 1500 µs |
| R6 | 输入角度限制在 `0 … INPUT_ANGLE_MAX` | 原代码收到 141–199 时会输出超过 1500 µs 的高电平（最大约 2130 µs） |
| R7 | **失控保护**：超过 500 ms 没收到数据，第 7、8 通道回到正前方对应的值（编码角度 90）。可以改成保持当前位置 | 原代码断线后会一直保持最后的角度 |
| R8 | **上电默认居中** | 原代码上电后、收到数据之前，第 7、8 通道输出 0 µs 高电平，也就是极限位置 |
| R9 | 可选的指数平滑 `SMOOTHING_ALPHA`，默认 1.0（关闭） | 可以减少抖动；打开后会增加一点延迟 |

## 4. 和原版行为不同的地方（上机前必看）

| 情况 | 原版 | 优化版 |
|---|---|---|
| 上电后、收到数据之前 | 第 7、8 通道高电平 0 µs | 居中：高电平 964 µs（编码角度 90） |
| 断线超过 500 ms | 保持最后的角度 | 回到居中（可改为保持） |
| 头戴端角度超出 -90°～+90° | 发出被截断的数值 | 限制在边界 |
| 接收端收到 141–199 | 高电平最大约 2130 µs | 限制在 1500 µs（`INPUT_ANGLE_MAX = 140`） |
| 通道值为 0 | 高电平约等于 0 | 最少 20 µs（定时器版的最短时间段） |
| 调试打印 | 每次循环都打印 | 默认不打印 |

`INPUT_ANGLE_MAX` 默认保持原版的 140，这样云台行程和原来一样。头戴端实际发送的范围是 0–181，如果想用满头部转动范围，可以改成 180，但改完需要重新确认云台的转动范围。

## 5. 已经做过的检查（都在电脑上完成，不是真实验证）

1. **语法检查**：用电脑上的 clang++ 配合模拟的 Arduino 头文件，对两个文件的两条编译路径（普通开发板 / ATmega328P）都做了语法检查，全部通过。
2. **PPM 逻辑模拟**：在电脑上反复调用接收端的定时器中断函数，统计每帧的各段时长：

   | 输入 | 第 7 / 8 通道高电平 (µs) | 同步段 (µs) | 每帧总长 (µs) |
   |---|---|---|---|
   | 上电无数据 | 964 / 964 | 4572 | 20000 |
   | 俯仰 120、偏航 7 | 1285 / 75 | 5140 | 20000 |
   | 俯仰 180、偏航 181（超出范围） | 1500 / 1500 | 3500 | 20000 |
   | 俯仰 0、偏航 1（最小值） | 20 / 20 | 6460 | 20000 |
   | 600 ms 没有数据 | 964 / 964 | 4572 | 20000 |

   这只是核对计算逻辑。真实的波形还会受中断响应时间、晶振精度等因素影响，需要用示波器或逻辑分析仪实测。

## 6. 建议的验证步骤

1. **编译**：在 Arduino IDE 中选择实际使用的开发板，分别编译两个程序。README 写的是 Nano 33 BLE，但原代码直接用 `Serial` 连接 HC-05，更像经典 Nano 的接法，请先确认板子型号。
2. **头戴端**：用 USB 串口监视器（HEX 显示）确认每 8 ms 收到一个字节，并且奇偶交替。注意：HC-05 连接时，串口监视器可能和它冲突。
3. **接收端波形**：用示波器或逻辑分析仪看 D2，确认一帧是 20 ms、8 个通道、500 µs 低电平脉冲，并检查抖动。
4. **失控保护**：给头戴端断电，确认 0.5 秒后第 7、8 通道回到居中。
5. **云台**：拆下螺旋桨，接上云台，确认方向、行程和中位与原版一致。
6. **偏航漂移**：和原版对比静止状态下偏航的漂移情况。H2 让 `mpu.update()` 调用更频繁，效果取决于 `MPU6050_light` 库内部计算时间间隔的方式，需要实测确认。

如果验证中发现问题，直接换回 `v1/firmware/head_unit/`、`v1/firmware/receiver/` 中的原始代码即可。
